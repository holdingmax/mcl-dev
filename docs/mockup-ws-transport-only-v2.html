FLOW SUMMARY SO Create → DO (pickup+delivery+BUP/Loose) → POD (upload signed DO + date/time) → Charge → Invoice
Transport-Only Flow — Simplified
Step What happens Status Billing
1. Create SO Client + cargo type + cargo lines (AWB/PO, pcs, kg, note). Minimal. requested —
2. Create DO Pickup + Deliver To + BUP/Loose + Driver + Trucking + Custody. Can create multiple DOs. in_progress —
3. POD / Close Delivery date/time + upload signed DO (optional) + receiver (optional). Generates transport charge. completed Charge generated
4. Invoice Normal billing flow: select SO, facturar. billed Invoice issued
Key differences vs regular SO:
  • No check-in, no WR, no reception, no screening/storage/in-out
  • SO creation is minimal — just client + cargo lines
  • DO = Pickup Order + Delivery Order (route, BUP/Loose, driver)
  • The signed DO IS the POD document (no separate POS/POD generation)
  • Billing charge generated at POD closure, not at DO creation
  • Signed DO upload is optional for closing (can upload later)
  • Does not appear in Inventory
Alternative considered: Generate billing at DO creation (like current flow) vs at POD closure. Current proposal: generate at POD closure because the service isn't complete until delivery is confirmed. This also means if a DO is cancelled before delivery, no charge is generated.
